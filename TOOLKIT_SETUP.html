For consultants and in-house teams

One download. A control panel for the whole toolkit.

Start the toolkit, create a private project from the examples, then use its cards to check dependencies, install supported R packages, start apps, run reproducible examples and prepare template projects. Names and folders are yours; nothing is configured for a particular client.

Start here: Download the complete toolkit ZIP · Preview the control panel and all 23 modules. The hosted preview opens browser demos and guides. Starting local apps or writing project files requires the downloaded launcher on your computer.

First use

  1. Download and extract the ZIP. Keep the complete extracted folder together. Do not start it from inside the ZIP.
  2. Install Python 3.10 or later if it is missing. Use the official Python installer or your organization's software portal. The launcher's missing-runtime message provides the next step. On Windows, enable the installer's PATH option if offered.
  3. Double-click the Start Toolkit file for your system. Use Start Toolkit.command on macOS or Start Toolkit.cmd on Windows. A small local server opens the control panel in your browser. On Linux, use the supplied Start Toolkit.sh launcher through your desktop's run/executable-file option.
  4. Create a private project from examples. Give it a neutral name such as Study workspace. The launcher makes a separate, complete copy of the toolkit and its fictional example data. Keep one project for each study or engagement.
  5. Choose a card and click its check or start action. Missing R packages can be installed with that card's Install button. Browser tools and guides need no R. The next table explains the separate runtime installers.

If your operating system blocks a downloaded launcher, review the file and use its normal trusted-app opening workflow or your organization's software process. Keep the launcher running while local apps or jobs are active; use the control panel's Stop action for a running app or job.

Install only the runtime your task needs

R apps and numerical examples

Install R through its normal installer or your approved software portal. The five apps require R 4.1 or later; the R template library documents R 4.4 or later. The worked study records the environment in its lockfile. Use Check, then the relevant Install action, and read the resulting log. Packages are installed in user storage. No terminal commands are required for these launcher actions.

Worked-study reports

Install Quarto using its installer. The study card checks for it and restores the study's R packages before reproduction. Restoring the lockfile may take time and may require approved system build tools on your machine. A failed check or install remains visible in the job log.

R analyses with SAS reference exports

Use guided study forms to select a design and outputs, upload CSVs, map columns and set analysis assumptions. Generate a revision, check its R environment, install missing packages through the button and run. The report and results ZIP include complete outputs and execution QC. Both TLF setup routes use R; native SAS reference exports remain available and unexecuted.

Local language-model projects

The LOCALMIND and interpretation cards prepare settings and open their source projects. Their guides describe the separately installed model runtime and model files. The toolkit does not download weights, accept model licenses or promise a working production model. The interpretation card's runnable action checks the deterministic number validator without a model.

Use your own inputs and keep your work

  1. Start from a known example. Run it once and read its output and log before adapting it.
  2. Use the card's input files. Download or open a listed CSV, preserve its headers and documented types/units, then upload the replacement into the selected private project. Upload validation checks the file structure; the app's checks and your review determine whether the input makes sense. UAT local input files are the parent uat_irt/templates/ files.
  3. Set up template studies with guided forms. The SAS/R libraries, monitoring, LOCALMIND and TLF interpretation cards offer study choices, CSV upload and column mapping, a preview, and a Generate action. Save a profile to reuse the choices; download the generated ZIP and read its setup report. No study-path or variable-name code edits are needed for supported choices. Generated TLF, monitoring and aggregate interpretation packages have Check, Install and Run actions. Each run retains separate results and diagnostics. LOCALMIND requires a separately configured model service. Use Open folder or Open in editor to inspect supplied programs. The sandbox, carryover, C-QTc and worked-study run actions rebuild their documented synthetic examples. They are not general analysis forms for uploaded participant data. In particular, the worked-study SAP settings JSON is generated by its R source and overwritten on reproduction.
  4. Save app exports before closing. Hours offers its ledger and change-order text; TRIALMON offers its worklist. UAT exports test results only, so preserve defect and traceability changes separately. Lifecycle and risk sliders are temporary what-ifs. Browser-only continuity and tracker workspaces need their own JSON/CSV exports.
  5. Export the private project. Retain the input files, edited source, outputs and run logs together. A project ZIP preserves files; it does not capture unsaved Shiny sessions or browser localStorage. The shared tracker's database and settings live outside the workspace ZIP. Use the tracker's separate backup controls to preserve those records and settings.

Configure and run a study with forms

Choose Set up R study outputs, Set up SAS study outputs, Set up monitoring checks, Set up language review , Set up vaccine analyses or Set up TLF draft report on the relevant module card.

  1. Choose the study and scope. Select a design, outputs or checks. No client is preselected.
  2. Map CSV inputs. Upload the requested files and map source headers. Confirm population flags, units, parameters, comparison labels and analysis windows against the study plan. Dose models require actual numeric doses.
  3. Preview. Resolve missing columns and invalid values. Read model assumptions and exclusions. Interpretation shows an editable factual paragraph; LOCALMIND findings start unapproved.
  4. Generate a revision. Its package retains configured inputs and programs, provenance, a setup report and a reusable profile. Generation itself does not run an analysis.
  5. Check and run. TLF, monitoring and interpretation revisions offer Check, Install packages and Run analysis. R is the runnable default, including the SAS TLF route. An installed R runtime is required; the toolkit links to its graphical installer. No command-line steps are required.
  6. Review and download. Each attempt has a separate results ZIP, HTML report, QC record and software versions. Tables/listings include all rows in CSV/RDS and paginated HTML; figures include PDF/PNG. Failed outputs make the run fail and retain diagnostics. No run approves itself.
  7. Reuse settings. Import a profile in another private project, add that project's data and preview again. Profiles transfer choices, not study data.

Native SAS exports remain unexecuted reference code. LOCALMIND needs a separately installed model service; no model, email service, scheduler or live feed is contacted by the deterministic analysis runner. Synthetic QC establishes the tested software behavior, not suitability or approval for a particular study.

Shared tracking and email

The tracker card opens its existing guided setup for accounts, permissions and optional SMTP. Preview messages before connecting your mail service. This local toolkit control panel does not publish a server, create a client deployment or send monitoring-template emails. A shared deployment uses your chosen host and its own settings.

When a check needs attention

Open the job log first: it records the attempted action, runtime findings and error. Install the named runtime through its graphical installer or your software portal, reopen the launcher if needed, and rerun the check. If a package requires a compiler or system library unavailable on your managed machine, use your approved R environment. Keep the example and modified project separate so a data or method change can be compared with the baseline.

Scope: every starter dataset is synthetic. A successful example run is evidence about that example. Study adaptation still requires reviewed inputs, methods and outputs. See the QC report and each module's limits. Source is available under the MIT license.
