From setup to complete results

  1. Choose your workflow. Operational apps start blank. Load your CSV files or deliberately choose the synthetic example. Method studies identify their simulated or fixed-example scope.
  2. Review your study definitions. Map source columns, select populations and outputs, and confirm units, visits, parameters, comparison labels and applicable thresholds. The toolkit does not choose an estimand or analysis plan for you.
  3. Validate and run. R and setup logic execute inside browser workers. Invalid inputs stop the run. Changes to inputs or settings invalidate old results; failed runs retain diagnostics.
  4. Review and save. Download complete reports, tables, figures, source and settings before closing. Configured SAS exports are available where a SAS twin exists; native SAS remains unexecuted reference code. Execution never grants scientific approval.

Analysis and operational-app uploads stay in session memory. Reset, reload or closing clears those sessions; exported workspace JSON and setup profiles support resuming. The existing offline tracker and continuity pages explain their own browser storage and export controls.

Browser compatibility and limits

Desktop Chromium is the main tested path for R computation. The Shiny launch pages detect startup failures and explain the known Safari/WebKit stack limitation; a page that has not started is never labeled ready. Keep the tab open while it computes. Large simulations and the full seeded-defect suite can take many minutes, depending on the device.

The analysis workbench accepts UTF-8 CSV files up to 16 MiB and 100,000 rows per feed, with a 256 MiB result-export limit. Use prespecified subsets or smaller output batches where appropriate; never omit eligible records merely to fit a software limit. Individual apps state their own capacities.

LOCALMIND manual review requires no model. Optional browser AI needs WebGPU, roughly 1.1 GB graphics memory and an explicit public-model download. Finding text is processed on the device. Suggestions remain unapproved and are not applied automatically. Model files may remain cached; workspace records do not.

Optional sharing, schedules and email

Shared accounts, unattended schedules, connected feeds and live email need an always-on service. They remain optional connections that each user or organization chooses; no client host, mailbox or account is embedded. Use the tracker’s guided shared setup to configure access and mail, preview messages and review its backup controls. Browser analysis works without those connections.

This release does not create a deployment for a specific client, automatically send messages, or configure a live clinical feed. A service’s access, retention and backup settings are separate from a browser results ZIP.

Optional desktop reproduction and larger projects

The original graphical desktop toolkit remains available. Download and extract the ZIP, install Python through its graphical installer if needed, then double-click Start Toolkit.command on macOS or Start Toolkit.cmd on Windows. On Linux, use your desktop’s run option for Start Toolkit.sh.

Create a private project from the fictional examples. The local control panel detects R and Quarto, provides package checks and installation buttons, and retains run logs. Install missing runtimes through their graphical installers or your organization’s software portal. Desktop model-service helpers and native SAS exports keep their documented requirements.

Export the complete private project to retain its files. Unsaved browser sessions and the shared tracker’s separately stored database/settings are not included; use each tool’s export or backup controls.

When a run needs attention

Read the on-page diagnostic and the downloadable execution log. Check mappings, required columns, units, missingness and study choices before rerunning. Reset cancels a browser session; save completed work first. A runtime or unsupported-browser failure is reported as a failure, not a successful analysis.

Scope: starter datasets are synthetic. Software QC establishes tested behavior, not approval or suitability for a specific study. See the QC report and the browser capability and verification guide. Source is available under the MIT license; the eCRF module retains its Apache-2.0 license.
