How the work is checked

The principles behind every page, the checks that run on this site and what they do not cover, the words used for execution status, and where AI tools were used.

01 · Principles

How I work

  • Validated systems own reported numbers
  • A named statistician signs every deliverable
  • This site uses synthetic data only

In a study, reported numbers come from validated, double-programmed SAS/R TLF programs on ADaM; NCA from Phoenix WinNonlin (version per the ADRG, currently 8.8) or PKNCA; CDISC conformance is checked with Pinnacle 21, which produces no reported numbers.

Validation harness gates

Ten gates run against this repository's own TLF pseudocode libraries and synthetic ADaM data. Most checks are structural (inventories, pattern scans, counts); G1 re-runs the synthetic study; G9 recomputes the sandbox's PK, bioequivalence and adverse-event results with separately written code; G5 is a manual record, not computed; G7 stays "not signed" until a named statistician signs for AI use. No gate has a human sign-off yet.

  1. G1Reproducibility & environmentgreenthe sandbox's eight committed output files regenerate byte for byte from code and seed, and every R program parses
  2. G2PK and count convention scansgreenPK programs use log-scale geometric statistics, counts use distinct participants, and the drafter's number check has a self-test (pattern scans; they do not show where a reported number comes from)
  3. G3Data structure & integritygreenthe analysis data passes the custom structural checks (not Pinnacle 21 or CDISC CORE), is intact, and PHI-free
  4. G4SAS/R twin structural paritygreenthe SAS and R twins line up program for program (structure only)
  5. G5Adversarial QC panelmanualno skeptical reader can break the deliverable
  6. G6Reporting conventionsgreenTLF numbering, scope and ICH E14 conventions hold (pattern checks, not a regulatory review)
  7. G7AI-governance documentation presentnot signedthe drafter's AI-use limits (frozen model, human gate) are written down and no PHI turns up (file scans); accountability needs a named statistician's signature, not yet given
  8. G8Package & GUI consistencygreenthe package is navigable, linked, and internally consistent
  9. G9Independent recomputationgreenthe sandbox's NCA parameters (ADPP) and printed results (geometric means and CV%, GMR and 90% CI, AE participant counts) match a separately written recomputation from ADPC, ADEX, ADSL and ADAE (same author: a re-derivation, not double programming by a second person)
  10. G10Harness sensitivitygreenthe harness's own reach: a pre-registered list of programming defects is planted one at a time in a throwaway copy, the outputs are regenerated so G1 cannot fire, and each defect is recorded as caught (by which gate or test), survived, equivalent or not applicable (QC-process engineering; it measures the harness, not a statistical method)

Seeded defects

Programming defects from a list fixed in advance are planted one at a time in a throwaway copy of the repository, and each is recorded as caught (and by which gate or test), survived, equivalent or not applicable.

Counts by class for this hand-picked, pre-registered list; they estimate nothing beyond it (no detection rate, no interval). Survivors are disclosures, not failures. EQUIVALENT is decided by diff on the shipped data, so it is not proof that a change has no effect.

Package check

python3 package_qc.py checks local links (HTML and Markdown), retired content, empty link cards, navigation and the README inventory, terminology, framing and count drift, and reads the text of every published spreadsheet, Word file, slide deck, PDF and JSON file for the same framing, terminology and spelling checks. python3 build_pages.py --check confirms that every generated page, region and readout matches its source and that every color pair meets its contrast floor. GitHub Actions runs both on every push and pull request. They check the package, not the statistics.

03 · Vocabulary

Status labels

Each module states what was actually executed, in these words:

Execution status, as used on every page
LabelMeaning
RunsExecuted here; the page says how and when
Parse-checkedThe code parses; it has not been run on data
Not executedWritten for a tool that was not available (SAS: no license)
Structural checkInventories, pattern scans or counts, not a numeric comparison
Manual recordEntered by hand, not computed
Under revisionKnown issues are listed on the page; fixes come in the next revision

The lifecycle labels are narrower still: Led owned, wrote or led the work in a job; Supported reviewed, contributed, or created or reviewed; Tools built shown only by independent work (code on this site or public drafts), not by job experience; Gap no job experience or no worked artifact yet.

04 · AI use

AI use

AI tools may draft or check text; they never produce a reported number.

Several modules were drafted with AI assistance; where an AI-agent review panel was used, the page says so, and human sign-off is recorded only where it was given (none yet in the validation ledger).
