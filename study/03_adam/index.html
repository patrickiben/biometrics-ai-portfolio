Stage 3: data standards

SDTM-like inputs, ADaM with admiral, specification checks and XPT

Supported (job): created or reviewed CDISC analysis specificationsExecuted hereGap: define.xml and ADRG not authored

Synthetic data only: simulated for a portfolio worked example; not real trial data and not a regulatory deliverable.

SDTM-like source domains are simulated by 03_adam/01_sdtm.R, which reuses the sim_lifecycle/ priors and one-compartment model (N = 40, seed 2026) and takes each participant's sequence from the stage 1 randomization schedule. ADaM datasets are derived with admiral 1.5.0 following its ad_adsl.R, ad_adpc.R, ad_adpp.R and ad_adae.R templates, checked against the specification with metacore 0.3.0 and metatools 0.3.0, and written as SAS XPORT v5 with xportr 0.6.0.

Template adaptations in ADPC (each one commented in 03_adam/03_adpc.R)

  • The analyte name joins PC and EX, because EXTRT carries the formulation (SIMDRUG TEST or SIMDRUG REFERENCE).
  • A pre-dose sample belongs to the dose that follows it (ARRLT below 0, NRRLT = 0), as the template's DTYPE COPY records do for repeated dosing.
  • BLQ values are 0 in AVAL (SAP, ICH M13A); the template's LLOQ/2 records are not created.
  • The sample that was not collected stays in ADPC with ANL01FL not Y, so a listing can show it.
  • derive_var_nfrlt() and convert_xxtpt_to_hours() are labeled EXPERIMENTAL in admiral 1.5.0; NFRLT is re-derived by plain arithmetic in stage 5 (Q4).

Specification

adam_spec.xlsx uses the Pinnacle 21 specification layout (Study, Datasets, Variables, ValueLevel, WhereClauses, Codelists, Dictionaries, Methods, Comments, Documents), which metacore::spec_to_metacore() reads. adam_spec.json holds the same tables for scripts and diffs. Both come from one definition in 03_adam/spec/build_spec.R. Variable labels follow CDISC naming (for example USUBJID, "Unique Subject Identifier").
