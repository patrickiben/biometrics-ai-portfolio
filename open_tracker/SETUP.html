Set up team access

Local setup, without terminal commands

  1. Download and unzip the toolkit

    Keep the whole folder together so the launcher can find its files.

    Download toolkit ZIP

  2. Open the launcher for your computer

    In the open_tracker folder, double-click Start Tracker.command on macOS or Start Tracker.cmd on Windows. It prepares the required components and opens your browser. A progress window may appear; you do not need to type commands.

    If Python is missing, install Python 3.10 or newer using the Python installer, then reopen the launcher.

  3. Create your first administrator

    Choose a username and password in the setup form. Start empty, or select the fictional example. Your private workspace is saved in your home folder and stays separate from the toolkit download.

  4. Use Settings to manage the workspace

    Add people, change permissions, preview email, and download backups with buttons. Open the same launcher next time to resume. Local mode is available only on your computer.

Team hosting, with a browser-led setup

Render is one optional shortcut for teams who want a hosted URL. The same open-source tracker can run on another suitable host using the Docker recipe.

You control the deployment. The shortcut opens your hosting account for review. A persistent disk requires a paid service; review the provider's current charges before deploying. This page does not create or purchase hosting.

  1. Review and deploy in your hosting account

    The supplied template includes persistent storage and disables automatic updates from this repository. Choose your service name and review the proposed resources.

    Open Render setup ↗ How the shortcut works

  2. Open the workspace and enter its setup key

    When the host reports the service is ready, open its URL. In the hosting dashboard, open Environment and copy the generated TRACKER_SETUP_TOKEN value into the workspace's setup-key field. This key is used only to create the first administrator; keep it private.

  3. Add people and share the workspace link

    In Settings → People, create individual viewer, editor or administrator accounts. Use Shared access to copy the workspace URL. Share each person's credentials through your usual private channel.

  4. Choose how email should work

    In Settings → Email, start with a local preview. To send messages, enter the SMTP details from your mail service and explicitly enable delivery. Use Send test for one chosen address. Saved settings apply automatically.

Use an existing host or another provider

The browser-setup Docker recipe uses the same setup form. An operator supplies the HTTPS URL, persistent storage, and a private setup key in the host's configuration screen. The team then manages accounts and email in the browser. See the hosting and operations guide for the complete recipe.

Everyday administration stays in the browser

People and permissions

Create accounts, change roles, reset passwords, and disable access. Everyone in a workspace can read its tracker; use separate deployments for separate access boundaries.

Email you control

Choose preview, off, or SMTP delivery. Preview messages without sending; test one explicit address before using automatic alerts.

Status and backups

Check workspace and notification status, copy the shared URL, and download a consistent database backup.

The public demo is a browser workspace. Private accounts and email settings belong to the workspace you run or host. The toolkit is a reusable evaluation tool, with no specific client service configured.
