Trial‑Management Validation Harness · evidence ledger

Ten gates for a clinical‑biometrics deliverable, run against this repository's own SAS/R TLF pseudocode libraries and synthetic ADaM data. Most checks are structural (inventories, pattern scans, counts); G1 re-runs the synthetic study; G9 recomputes the sandbox's PK, bioequivalence and adverse-event results with separately written code; G10 reports what the harness catches when defects are planted on purpose; G5 is a manual record, not computed; G6 checks that every QTc change figure uses one reference-line convention (0, 30 and 60 ms, the ICH E14 categorical thresholds); G7 stays “not signed” until a named statistician signs for AI use; SAS is never executed (no license). The organizing principle is the split you see in every row below: automate detection and re‑execution; reserve the final decision for the qualified biostatistician. What the harness catches

A seeded-defect check (G10). Realistic programming defects from a list fixed in advance are planted one at a time in a throwaway copy of this repository. After each one the copy's outputs are regenerated, so G1's byte-for-byte check cannot fire; then the other gates and the module tests run, and the result is compared with an unmutated copy run the same way. Caught lists the layers that failed. Survived means no layer failed. Equivalent means no layer failed and no output or printed result differed (shown by diff, not assumed). The list is hand-picked, so the counts describe this list only: they are not a detection rate and carry no interval. Survivors are reported as what the harness misses, not hidden.

What the 2026-10-25 run shows. G1 to G8 caught none of the seven numeric and counting defects (D05 to D11); only the independent recomputation (G9) did. D01 was stopped by the generator's own consistency assertion before G3 could see it. The TRIALMON defects (D12 to D14) were caught only by TRIALMON's tests, which run_harness.sh does not run. All 17 outcomes matched the predictions registered in advance; the predictions came from the same author reading the gate code, so the match is not an independent test.

Registry: teeth/defects.csv (file, exact text replaced, replacement, predicted catcher and rationale per defect), frozen by its SHA-256 in teeth/defects.sha256 before the first run; the runner refuses an edited registry. Runner: teeth/run_teeth.sh with teeth/apply_defect.py. Results: teeth/results/summary.json and the dated CSV beside it. G10 turns “stale” when the registry or any gate script changes after the run. Layers: G1 to G9 and the module tests (TRIALMON testthat files, the UAT logic test); “driver error” means run_lifecycle.R stopped with an error, and “generator error” that simulate_study() itself did.

Tools built: QC-process engineering adapted from the teeth check and method-invariance grid in my consilience-engine software. It measures the harness itself and is not a statistical method. The Hy's Law grid in the TRIALMON console is a structured sensitivity analysis of SAP conventions. Synthetic data; SAS not executed.

Prior art first. Mutation testing (DeMillo, Lipton and Sayward, “Hints on test data selection,” Computer 11(4):34–41, 1978) and error seeding (Mills, IBM report, 1972) plant known faults to measure a test suite; the R package muttest (0.3.0, CRAN, July 2026) does this for R code. Zheng (JSM Proceedings 2019) models the errors that independent dual programming misses with a Poisson process, a model rather than an experiment. The grid follows multiverse analysis (Steegen et al., Perspectives on Psychological Science 11(5):702–712, 2016) and specification curves (Simonsohn, Simmons and Nelson, Nature Human Behaviour, 2020), in the spirit of ICH E9(R1) sensitivity analyses and FDA's July 2009 DILI guidance. What is new here is no new statistics: it is measuring which defects this clinical QC harness catches against a list registered before the run (a literature search for this build found no published example, which does not show there is none), and making each potential Hy's Law flag's dependence on SAP conventions explicit.

Source of the method: Iben P. Which data modality recognizes a gene set? A domain-agnostic consilience engine. In peer review at PeerJ (author draft exported 13 July 2026). Software: doi:10.5281/zenodo.21399794; code: github.com/patrickiben/consilience-engine.
