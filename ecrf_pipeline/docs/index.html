eCRF review workspace

Four client-neutral tools for reviewing clinical data extracts. Upload your CSV files, map their fields and run the checks directly in your browser. No installation, account, code editing or command line is required.

  • Open a tool
  • Guided user guide
  • Historical evaluation
  • Worked case study

Every tool starts blank. Load synthetic example is optional and uses fictional data. No client data or licensed MedDRA dictionary is bundled. Your own coding data requires your own dictionary CSV.

Choose a tool

Coding QC assist

Upload study CSVs and a dictionary CSV. Select verbatim and identifier fields, map dictionary terms, codes, hierarchy and currency, then set a review threshold.

Download candidate terms, scores, selected inputs, mapped dictionary and audit. Every candidate stays unreviewed. Lexical matching does not resolve clinical meaning or approve SDTM codes.

De-identification review assist

Select CSV fields, identifier patterns and additional literal terms. Choose which scanned fields belong in the redacted export.

Download redacted field copies and an audit separately from the optional sensitive-review package containing originals and matched spans. Review remaining text and headers: this does not establish complete anonymization.

Participant risk screening

Upload one study's safety domains. Map fields and categories, confirm units, and set screening thresholds and category cuts.

Download rule-based safety/discontinuation indices with contributing signals, coverage and settings. Scores are screening indices, not probabilities; missing domains are not assessed.

Anomaly and drift screening

Upload a wide CSV. Select participant and measurement fields, declare units, and choose explicit reference/current visits and optional lab/site groups.

Download numeric outliers, bounded distribution comparisons, text-isolation screens and audit. Paired visits require complete matched participants and stable lab/site assignments. These are screening methods, not a general longitudinal model.

Upload, map, run and save

  1. Open a tool. Start with your own files, or deliberately load its synthetic example to learn the controls.
  2. Upload UTF-8 CSV. Use unique nonblank headers and consistent rows. The form checks size, schema, numeric values where needed and unsupported filenames.
  3. Complete the guided mappings. Review the selected fields, units, dictionary and criteria before running. Default thresholds are illustrative, not a client protocol or SAP.
  4. Run and review. Changing files or settings clears old results and downloads. Results support human review; they do not make clinical, coding or privacy decisions.
  5. Download the complete review package. Save outputs before resetting, reloading or closing the tab. Reset clears the current workspace.

The User Guide describes every form and output. Optional native operation remains available for filesystem inputs, SAS files and learned-model runtimes.

Processing and exports

The Python apps run in your tab through stlite and Pyodide. The page loads software from the toolkit and declared runtime sources; the app does not send uploaded study files to a server. Asset providers receive ordinary requests, including your IP address. Study files and results are session-only; only your theme preference is saved in browser storage.

CSV exports escape spreadsheet formulas, including text headers. Audits record mappings, input hashes, settings and the algorithm used. Complete packages are ordinary review files, not protected audit trails or electronic signatures. PHI's sensitive-review package deliberately contains original data and must be handled separately from redacted exports.

The browser uses lexical coding, guarded identifier rules, weighted risk indices and robust screening methods. It does not run the optional native Needle3, Laya, XGBoost, Isolation Forest or Sinkhorn model paths.

Evidence and limitations

The evaluation and worked case study preserve the original synthetic/native evidence. On that held-out synthetic coding set, rank-1 accuracy was 78% for the native learned path and 54% for the lexical path. The de-identification evaluation left 91 versus 108 of 308 identifiers readable. Those measurements do not establish accuracy for your study, dictionary or settings.

Risk and anomaly have known-answer QC, not measured clinical accuracy. The historical automatic-commit labels and original-plus-sanitized PHI columns belong to the original/native implementation; today's browser flow keeps coding candidates unreviewed and separates redacted output from sensitive originals.
